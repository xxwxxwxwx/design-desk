# 饭团小红书招募海报

面向非设计运营人员，将真实商家素材和活动事实制作为一张可下载的 `1080×1440` PNG。对外是一个 Skill，内部分为主视觉生成和固定信息条合成两个阶段。

## 输入合同

- `1–9` 张生成素材，每张只能标记为“真实产品”或“风格参考”。真实产品必须保留产品身份、容器、包装、数量、比例和识别特征。风格参考必须先提取可复用的视觉配方，包括文化与空间语境、背景环境、材质纹理、配色对比、字体气质、图形母题、光线、影像处理、构图节奏、密度和能量感，并将这套视觉世界贯穿背景、氛围、字体处理、装饰图形和产品呈现。传递风格而不复制源内容；不得带入其具体产品、商家身份、文字、数字、价格、Logo、促销说法或活动事实。
- 商家 Logo 单独输入，不占 9 张素材额度，不发给图片模型重绘。
- 商家名、招募类型、人数、时间、地址、体验内容或额度、报名规则。
- `overlay_mode` 为 `co_brand` 或 `fantuan_only`。`co_brand` 必须提供真实商家 Logo。

## 执行流程

1. 实际查看本次素材，识别产品、数量、名称对应与风格参考。名称不能仅凭颜色或上传顺序猜测；确有歧义时确认。提取本次视觉方向，不将某个商家的场景或装饰固化为通用模板。
2. 读取 [版式规则](references/layout-rules.md)，整理逐字活动文案与仅供执行的制作要求。先考虑完整地址和报名规则需要的空间，再整体规划中央区域内标题、产品、产品名与详情的关系；不固定内部高度、顺序或压缩步骤。
3. 将上述判断组织为本次专属生成指令，连同通用边界提交。全部前景只在中央 `13.2%–86.1%` 设计区；背景自然贯穿四边，上下保护区不放文字、产品、装饰或面板。安全区参考图仅本地检查，不发送给模型。运行时通用规则在 `server.py` 的 `prompt_for()`，按版式规则中的 v4 结构条件化组织，本 Markdown 不会自动进入 API 请求；专属指令须明确经过可用的请求字段传入。保存实际提交内容，未核实的运行版本不得用磁盘代码代替。
4. 获得本轮付费授权后生成一次，保存原始结果，并安全适配为 `1080×1440`，不拉伸或改变产品身份。不得自动付费重试。
5. **实际查看基础图**，读取 [生产验收](references/production-qa.md)，逐项检查保护区、完整文案、产品与名称对应、风格延续和可读性。仅写在 Prompt 中的自检不算已执行视觉检查。任一硬性项失败，记录为不合格并组织本张图的针对性修正；再次付费先取得授权，修正后重新检查。
6. 读取 [固定模板保真](references/template-fidelity.md)，通过 `scripts/compose_poster.py` 原样合成 Logo 和固定条；**实际查看合成结果是否遮挡内容**。可为诊断合成预览，但不合格基础图即使合成成功也不能作为合格成品。
7. 运行 `scripts/validate_output.py`。机械检查和基础图、合成图视觉检查都通过，才可称为合格成品；尚未看图则明确标待验收。

工作台当前仍是单次生成与本地合成，以上看图和修正由协作助手执行，不具备自动视觉审核或自动修正能力。Skill 文档更新不代表这些能力已经接入程序。后续任务复用此流程，具体风格判断和修正指令每次根据素材与结果重新组织。

## 不可妥协的边界

- 活动事实逐字保留，未提供的日期、地址、人数、额度或福利不得补造。
- 产品、容器、包装、数量和宽高比以真实素材为权威；参考图中的商品、价格和旧文案不得混入。
- 图片模型不得生成饭团 Logo、商家 Logo、联名面板或底部搜索条。
- 固定模板不得通过生成模型重绘、变形、变色或近似模仿。
- 上下预留区不得出现文字、产品、Logo、面板、边框、阴影、徽章或占位说明。
- 安全区检查、固定像素检查与最终视觉验收是不同层次；机械验证成功不等于业务视觉验收已完成。
