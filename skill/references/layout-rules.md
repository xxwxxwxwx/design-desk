# 版式与信息层级规则

## 标准画布骨架

以 `1080×1440 px`、3:4 竖版为唯一成品规格。在生成指令中先按相对比例定义构图，将精确像素尺寸放在独立输出要求中，不描述服务器裁切。

| 区域 | 建议范围 | 用途 |
|---|---:|---|
| 顶部保护区 | 0%–13.2% （0–189 px） | 只保留连续自然背景，后期叠加饭团与商家联名信息 |
| 中央设计区 | 13.2%–86.1% | 自由安排标题、产品、装饰与完整活动信息，不规定内部分区高度 |
| 底部保护区 | 86.1%–100% （1240–1439 px） | 只保留连续自然背景，后期叠加饭团固定搜索横条 |

先铺满连续背景，再冻结上下保护区，只在中央 `13.2%–86.1%` 设计区放置可见海报内容。主标题、产品与活动信息区可以在中间边界适度交叠，但任何文字、图标、产品、面板、边框或阴影都不得进入上下保护区。最终左右安全距离至少为画布宽度的 `6%`（64 px）。

`assets/layout-safe-zone-reference.svg` 和对应 PNG 保留用户提供的原始物理占位：顶部深灰区为 `0–159 px`，底部深灰区从 `y=1315` 开始。派生的 `assets/layout-safe-zone-generation-guide.png` 将本地检查范围扩大为顶部 `0–189 px` 和底部 `1240–1439 px`。这些遮罩不发送给 KIE，仅用于本地安全区检查，避免影响海报配色、矩形和构图。

## 阅读顺序

阅读层级以活动主题、真实产品和参与信息容易理解为目标；以下优先级仅供参考，不要求固定上下顺序、分栏、高度或卡片结构。

单商家海报优先级：

1. 招募人数与“品鉴官／体验官”。
2. 商家或产品主题。
3. 体验内容、额度或福利。
4. 时间、地址和报名规则。

多商家活动优先级：

1. 整体活动主题。
2. 各商家名称。
3. 每家招募人数与体验内容。
4. 总人数、总时间、地址和报名规则。

不要强制所有海报都把招募人数做成最大标题。单商家通常突出人数；多商家活动通常先突出总活动主题。

## 根据素材数量选择版式（可选参考，非固定模板）

| 输入情况 | 默认版式 |
|---|---|
| 单商家、1–3 个产品 | 中央大产品场景，一主两辅或均衡三角构图 |
| 2 款套餐或 2 个主推品 | 左右并列，使用相同标签结构 |
| 3 个商家 | 上二下一或错落卡片，每张卡保持相同字段 |
| 3 道并列产品 | 一主两辅、三角构图或三卡布局，不随机堆叠 |
| 4 款菜品 | 2×2 等尺寸矩阵 |
| 1 个主产品与辅助照片 | 主产品约占产品区三分之二，辅助照片做小卡片 |
| 产品多、文字少 | 放大真实产品和场景，保留呼吸感 |
| 规则或地址多 | 扩大底部信息卡，减少装饰，不缩小到难以阅读 |

## 信息密度

信息少时，放大真实产品、增加与商家相关的场景氛围和留白；不要虚构卖点填满画面。

在中央设计区内自由构图。根据参考图的视觉语言、产品数量和文案长度，自主决定标题位置、产品大小、信息分组、装饰形式与留白。上下保护区边界保持不变。

允许为强化主题和方便阅读适度重复信息。输入字段用于理解内容，不是必须照搬的表格结构；不要将“主标题”“商家名称”“招募类型”等管理字段名称、输入说明、文件名或扩展名印在画面上。活动详情可使用便于观众理解的简短标签。

空间紧张时自主调整构图和视觉比重，优先保证完整文案与可读性，不规定压缩顺序。保留产品比例、数量和全部独有事实；不得删减地址或报名规则，或让内容越界；最低可见前景元素必须在 `y=1240` 之前结束。

背景的颜色、材质、纹理、光线和环境表面应自然贯穿上下保护区并延伸至四边。保护区仅排除前景信息，不是白色留边或独立面板；不得额外添加白条、突兀背景截断或分区边界。只有参考图背景方向本身适合白色时才使用白色。

## 视觉适配

- 商家现有品牌与产品气质决定主视觉。餐饮突出食欲、份量和套餐关系；饮品突出口味、季节和材质感。
- 先提取风格参考的文化与空间语境、背景环境、材质纹理、配色、光影、字体气质、图形母题和版面节奏，并将这套整体视觉世界重新应用于当前海报；不得复制其具体产品、商家身份、文字、价格、Logo或促销事实。
- 标题通常控制在 1–2 个视觉层级、最多 2–3 行；人数数字可以成为唯一强调色。
- 同一画面最多采用两套主要字体风格。标题可以有主题感，活动信息必须清晰易读。
- 多产品必须形成明确阵列，盘碗不能拉伸，产品不得顶住标题或安全区。

## 固定 Prompt 执行与留档

生成时补充绝对坐标：全部前景外缘（含描边、阴影、产品配料和面板）限于 x=65–1014、y=191–1238，边界内保留呼吸空间。将中央区视为完整可用版面，先同时容纳标题、产品和全部参与信息；不规定内部高度、顺序或压缩步骤。坐标仅用于构图，不印入画面。

事实值与制作要求分开传递；其他要求只执行，不作为逐字印出的活动文案。未填写主标题时，自动拟题的指令也只执行。禁止复刻输入表单、键值表格或字段清单；允许自然的信息横条和面向观众的简短标签。

每个新任务在 request.json 保存生成时的完整 prompt、prompt_version 和 prompt_sha256；旧任务不回填、不将当前代码重建的 Prompt 当成历史发送原文。留档不代表 API 接收或视觉验收通过。

## 可读性约束（不限定中央构图）

主标题最多 2–3 行，招募主题在手机缩略图中容易识别。长报名规则按语义分行；地址完整保留，可自然换行。不得无限缩小字号塞进剩余空间，应在中央区域内重新平衡构图。需要产品名时，准确标注在对应真实产品附近，关系清楚；保留包装真实印刷，不把文件名当产品名。

## 防止沿用参考版式导致越界

把参考的视觉语言与位置分开：延续其空间语境、材质、光线、字体与图形气质，不能直接沿用其贴顶标题或贴底详情的位置。先整理完整独有文案，尤其长地址与报名规则，将它们和标题、产品一起规划在中央区，而非最后补进剩余底部空间。对包含描边、阴影、配料、面板的整体外缘检查边界。无法容纳时重新平衡整体构图，不规定内部区域比例或固定压缩步骤。

重复应服务阅读；不要因参考图有多个招牌就机械增加独立商家牌或重复主题。此规则不禁止有用的适度重复，也不预设所有任务都要删除招牌。

## Prompt 组织方式（v4）

运行时按“硬边界 → 本次准确文案 → 图片角色与适用规则 → 本次制作要求 → 条件化构图决策 → 可读性 → 自检与输出”组织一次请求。准确文案使用带元数据键的 JSON 区块；键不印入海报，制作要求独立，不混作逐字文案。同一角色规则只写一次，不在多个段落反复堆叠保护区和风格约束。

代码仅根据字段是否存在和上传角色选择适用指令：有无明确标题、有无地址/报名规则、有无产品/风格参考。它不看图、不推断具体风格，也不将图片张数当产品数。图像内容理解仍交给图生图模型；明确名称对应来自用户提供的信息。无风格参考时不套用既往商家场景。中央自由构图、完整文案和保护区边界保持不变。

此组织方式属于固定模板的条件化拼接，并非独立助手模型生成 Prompt B；结构检查不证明视觉改善。生效需要运行服务加载对应代码，重启前应保留表单并考虑内存 Key 会清空。
